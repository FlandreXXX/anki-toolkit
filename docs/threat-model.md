# Модель угроз Anki Toolkit

## Текущая поверхность

CLI принимает недоверенные аргументы, путь из окружения и JSON с диска. Локальный процесс работает с полномочиями запустившего пользователя. Конфигурация ограничена 64 КиБ, читается из обычного файла и проверяется по строгой схеме до использования. Для постоянных данных требуются абсолютные пути. Ошибочная конфигурация прерывает диагностику, системная причина сохраняется внутри цепочки ошибок.

Вывод `doctor` намеренно показывает эффективные пути. Они могут содержать имя пользователя и структуру его каталогов. В stderr и публичные ошибки попадают фиксированные сообщения, коды и идентификаторы источников. Содержимое файла, сырое окружение, аргументы и системные тексты ошибок остаются за этой границей.

Текущие операции читают конфигурацию и метаданные. Тесты запускают бинарник с временными каталогами и проверяют их содержимое до и после вызовов. Сетевые клиенты и телеметрия отсутствуют. Доступ к пользовательскому пути на сетевой файловой системе, в том числе UNC, обслуживает сама ОС.

Диагностика `doctor` наблюдает метаданные по имени пути: её проверка следует правилам ОС для символических ссылок и точек соединения каталогов (junction), а между проверкой объекта и чтением он может измениться. Успешная проверка пути подтверждает только те метаданные, которые наблюдались при проверке. Чтение конфигурации устроено иначе: тип объекта проверяется по метаданным фактически открытого дескриптора, а не по имени, поэтому подмена имени между открытием и проверкой не подменяет читаемые данные; на Unix-платформах, включая Linux, открытие не ожидает на FIFO. Ограничения сохраняются: путь может быть подменён до открытия, содержимое уже открытого файла может измениться во время чтения, сетевой файловый ввод-вывод и синхронные вызовы ФС не прерываются отменой, а межпроцессные гарантии отсутствуют. Проверка полномочий записи, защита от гонок при записи и ограничения корневого каталога потребуются вместе с изменяющими операциями.

## Будущие границы

Недоверенные экспорты, медиа, пути из коллекций и ответы локальной интеграции потребуют валидации на своих границах. CLI и MCP должны вызывать общие прикладные операции. MCP сам по себе не является границей авторизации. Доступ локального процесса к файлам ОС определяется полномочиями ОС и не ограничивается одними агентскими скиллами. Разрешение на локальную правку не включает разрешение на импорт в Anki.

## Цепочка поставок и артефакты

Продукт использует стандартную библиотеку Go. CI берёт версию Go из `go.mod` и фиксирует версии внешних Actions по полным SHA. Тесты используют синтетические данные. Локальные результаты проверок хранятся в игнорируемых артефактах задачи, пользовательские данные размещаются вне дерева проекта по умолчанию. Правила Git ограничивают случайное добавление локальных артефактов. Уже отслеживаемые файлы и принудительное добавление через `git add -f` остаются под контролем пользователя.
