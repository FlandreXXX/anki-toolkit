# Модель угроз Anki Toolkit

## Текущая поверхность

CLI принимает недоверенные аргументы, путь из окружения и JSON с диска. Локальный процесс работает с полномочиями запустившего пользователя. Конфигурация ограничена 64 КиБ, читается из обычного файла и проверяется по строгой схеме до использования. Для постоянных данных требуются абсолютные пути. Ошибочная конфигурация прерывает диагностику, системная причина сохраняется внутри цепочки ошибок.

Вывод `doctor` намеренно показывает эффективные пути. Они могут содержать имя пользователя и структуру его каталогов. В stderr и публичные ошибки попадают фиксированные сообщения, коды и идентификаторы источников. Содержимое файла, сырое окружение, аргументы и системные тексты ошибок остаются за этой границей.

Текущие операции CLI читают конфигурацию и метаданные. Тесты запускают бинарник с временными каталогами и проверяют их содержимое до и после вызовов. Сетевые клиенты и телеметрия отсутствуют. Доступ к пользовательскому пути на сетевой файловой системе, в том числе UNC, обслуживает сама ОС.

Диагностика `doctor` наблюдает метаданные по имени пути: её проверка следует правилам ОС для символических ссылок и точек соединения каталогов (junction), а между проверкой объекта и чтением он может измениться. Успешная проверка пути подтверждает только те метаданные, которые наблюдались при проверке. При чтении конфигурации предварительная проверка по имени позволяет отклонить специальные объекты, которые могут не открываться. Перед чтением тип проверяется по метаданным фактически открытого дескриптора, поэтому последующая подмена имени не подменяет читаемые данные. На Unix-платформах, включая Linux, открытие не ожидает на FIFO. Ограничения сохраняются: путь может быть подменён до открытия, содержимое уже открытого файла может измениться во время чтения, сетевой файловый ввод-вывод и синхронные вызовы ФС не прерываются отменой, а межпроцессные гарантии отсутствуют. Проверка полномочий записи, защита от гонок при записи и ограничения корневого каталога потребуются вместе с изменяющими операциями.

## Чтение экспорта CrowdAnki

Доменное ядро обрабатывает недоверенный JSON. Оно отвергает повторные ключи и неверный Unicode, ограничивает байты, глубину и размер типизированного представления. Точный исходник занимает один буфер, структурная сериализация выделяет отдельный буфер вывода. Крупное отдельное значение и синхронный вызов ОС завершаются до ближайшей проверки отмены. Лимиты не гарантируют фиксированное потребление памяти или время на сетевой файловой системе.

Файловый адаптер читает один обычный `deck.json` в явно переданном каталоге. Он отвергает конечные символические ссылки и точки повторного разбора. На Linux каталог закрепляется дескриптором, а `O_PATH` открывает конечный объект только для проверки типа. Чтение начинается после переоткрытия проверенного дескриптора через `/proc/self/fd` и повторной проверки его идентичности. При недоступности procfs чтение завершается отказом. На Windows предварительная проверка дополняется открытием с `FILE_FLAG_OPEN_REPARSE_POINT` и проверкой фактического дескриптора. Windows-путь к самому каталогу и его предкам разрешает ОС и может быть подменён до открытия файла. Предки переданного каталога на Linux тоже разрешаются ОС до закрепления каталога. Пространства имён устройств, именованных каналов и почтовых слотов Windows отклоняются.

Дескриптор защищает от подмены конечного имени после открытия. Сам файл может меняться во время чтения. Чтение не является снимком, контролем доверенности каталога или защитой от изменения монтирований и жёстких ссылок. Адаптер работает только на чтение. Код не открывает медиа, `import_config.yaml` и профили Anki, не исполняет HTML/CSS, не передаёт экспорт по сети. Исходные ошибки с приватными путями и фрагментами данных остаются в цепочке внутренних причин.

Переданный путь не нормализуется лексически: разрешение `..` и символических ссылок на предков выполняет ОС. Лексическая нормализация дала бы другой каталог для пути, где `..` идёт после ссылки, и молча прочитала бы чужой экспорт с тем же именем файла. Проверка метаданных и открытие на Windows используют один и тот же путь, поэтому правила нормализации Win32 применяются к ним одинаково.

## Будущие границы

Медиа, пути из коллекций и ответы локальной интеграции потребуют валидации на своих границах. CLI и MCP должны вызывать общие прикладные операции. MCP сам по себе не является границей авторизации. Доступ локального процесса к файлам ОС определяется полномочиями ОС и не ограничивается одними агентскими скиллами. Разрешение на локальную правку не включает разрешение на импорт в Anki.

## Цепочка поставок и артефакты

Продукт использует стандартную библиотеку Go. CI берёт версию Go из `go.mod` и фиксирует версии внешних Actions по полным SHA. Тесты используют синтетические данные. Локальные результаты проверок хранятся в игнорируемых артефактах задачи, пользовательские данные размещаются вне дерева проекта по умолчанию. Правила Git ограничивают случайное добавление локальных артефактов. Уже отслеживаемые файлы и принудительное добавление через `git add -f` остаются под контролем пользователя.
