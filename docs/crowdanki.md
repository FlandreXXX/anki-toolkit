# Поддерживаемый формат CrowdAnki

`internal/crowdanki` читает один JSON-документ UTF-8 с корневым объектом и точным `"__type__":"Deck"`. Ключи регистрозависимы. Идентичности и строковые значения сохраняют регистр, пробелы и Unicode.

| Представление | Интерпретируемые свойства |
| --- | --- |
| `Deck` | `__type__`, `name`, `crowdanki_uuid`, `children`, `notes`, `note_models`, `deck_configurations`, `deck_config_uuid`, `media_files` |
| `Note` | `__type__`, `guid`, `note_model_uuid`, `fields`, `tags` |
| `NoteModel` | `__type__`, `crowdanki_uuid`, `name`, `type` (обычный `0`, cloze `1`), `flds`, `tmpls`, `css`, `req` |
| `FieldDef` | `name`, `ord`, `description` |
| `TemplateDef` | `name`, `ord`, `qfmt`, `afmt` |
| `DeckConfig` | `__type__`, `crowdanki_uuid`, `name`, остальные параметры доступны как JSON |
| Объявления медиа | Имена и их порядок в `media_files` каждой колоды |

Порядок и принадлежность задаёт `children`, а имена колод, включая `::`, хранятся как строки. Объявления моделей и конфигураций читаются по всему дереву. Заметки принадлежат непосредственно узлу с массивом `notes`. Карточки представлены моделью и шаблонами. Значения `req`, HTML/CSS и данные планировщика сохраняются как данные. Файловый адаптер открывает только `deck.json`, а наличие объявлений медиа не подтверждает наличие бинарных файлов.

## Разбор, представления и сохранность

- `Parse(ctx, reader, limits)` отклоняет неверный синтаксис, UTF-8, одиночные суррогаты, повторные декодированные имена свойств, второй документ и мусор. Синтаксически правильный корень другого типа даёт `schema`.
- Повреждения ниже корня остаются доступны для диагностики. `Object.Property` открывает любое свойство, а `Value.Kind` отличает отсутствие от `null` и других типов. `List` сохраняет места всех элементов, включая `null` и элементы ошибочного типа. `Document.Walk` посещает объекты колод в прямом порядке обхода. Вложенные коллекции задают тип сущности при отсутствующем маркере. Явно повреждённый маркер препятствует разрешению сущности.
- `Original` возвращает копию точного исходника со всеми пробелами и экранированием. `Encode` собирает JSON из свойств и элементов представления и сохраняет целиком непрозрачные значения. Обе операции создают отдельный буфер. Семантическая сериализация сохраняет все ключи, числовые лексемы, типы, порядок массивов и значения. Она может изменить форматирование объекта и массива.
- `Limits` по умолчанию допускает 64 МиБ входа, 128 уровней JSON и 1 048 576 свойств и элементов материализуемых представлений. Эти пределы регулируют ресурсы приложения. Ноль выбирает значение по умолчанию, глубину можно поднять до 1024. Бюджет представлений ограничивает количество выделяемых структур независимо от объёма строк и чисел. Размер контролируется при чтении с проверкой одного байта сверх лимита.
- Отказы разбора имеют коды `syntax`, `schema`, `limit`, `read`, `canceled`. Позиция в байтах указывается, когда применима. Сообщение безопасно для вывода. Причины чтения и синтаксические ошибки доступны через `errors.Unwrap` для внутренней диагностики.

## Связи

UUID должен иметь шестнадцатеричную форму `8-4-4-4-12`. Сравнение точное, включая регистр. GUID — любая непустая строка. Справочники принадлежат одному документу. Запросы `*Declarations` возвращают все места объявления валидной идентичности. Для дубликатов колод и заметок выбор всегда неоднозначен. Повторные модели и конфигурации разрешаются однозначно только при совпадении полного содержимого, включая неизвестные свойства, порядок массивов и числовые лексемы. Пробелы, порядок ключей объектов и эквивалентное экранирование строк при сравнении не учитываются. В таком случае возвращается первое место по порядку дерева.

`ResolveField` и `ResolveFieldOrd` используют цепочку `Note.note_model_uuid → NoteModel.crowdanki_uuid → FieldDef.ord → Note.fields[ord]`. Имена и `ord` уникальны в пределах модели. Позиции образуют диапазон от нуля до числа определений минус один, а количество значений совпадает с числом определений. Выбранное значение должно быть строкой, в том числе пустой. `OrderedFields` даёт копию списка определений в порядке `ord` без перестановки исходного массива. Отказы разрешения различают `missing`, `invalid`, `unresolved` и `ambiguous`.

## Файловый адаптер и будущие области данных

`internal/crowdankifs.Read` принимает абсолютный нативный путь и передаёт открытый обычный файл тому же парсеру. Для файловых ошибок существуют коды `directory_required`, `missing`, `wrong_type`, `unavailable`, `canceled`. Платформенная граница подробно описана в [модели угроз](threat-model.md).

`decks/input` и `decks/output` — будущие логические области доверенных экспортов и рабочих копий соответственно. Их размещение будет определено вместе с хранилищем и обменом. Текущий парсер принимает явно переданный каталог независимо от его имени. Планируемый доступ к доверенной области потребует отдельного владельца.

Исходный экспортёр CrowdAnki помещает общие определения в корень. Чтение объявлений по дереву поддерживает и представления из предшествующего проекта. В отличие от его Rust-модели с плоским значением коллекции по умолчанию, здесь отсутствие, `null` и пустое значение сохраняются раздельно. Полнота совместимости с версиями Anki зависит от будущей проверки живого импорта.
