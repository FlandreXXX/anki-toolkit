# Архитектура Anki Toolkit

## Границы компонентов

| Компонент | Ответственность |
| --- | --- |
| [`cmd/anki-toolkit`](../cmd/anki-toolkit/main.go) | Подключение окружения, сигналов процесса и потоков ввода-вывода. Преобразование результата CLI в код процесса. |
| [`internal/cli`](../internal/cli/cli.go) | Разбор аргументов, справка, вызов операций и представление результатов. |
| [`internal/app`](../internal/app/app.go) | Прикладные операции `Version` и `Doctor`, типизированные исходы, работа с отменой и смысл статусов диагностики. |
| [`internal/config`](../internal/config/config.go) | Приоритеты конфигурации, строгая проверка JSON и платформенных путей. |
| [`internal/version`](../internal/version/version.go) | Каноническая версия продукта. |

Точка входа связывает CLI с прикладным сервисом. Сервис использует конкретный резолвер конфигурации, сведения о среде выполнения Go и метаданные файловой системы. CLI получает готовый `DoctorResult` и отвечает за представление его полей. Будущий MCP-адаптер сможет вызывать те же операции с `context.Context` и явными параметрами. Доменные правила CrowdAnki появятся с соответствующими операциями. Они должны оставаться независимыми от CLI, MCP, SQLite и платформенных файловых API.

Прикладные операции проверяют отмену до начала работы и между шагами. На уровне процесса контекст получает сигналы прерывания и завершения, которые ОС доставляет Go. Уже начатый синхронный вызов файловой системы должен вернуться в приложение, прежде чем отмена будет обработана.

## Машинный результат

`--json` перед командой выдаёт один объект UTF-8 с `schema_version: 1`, `operation` и `status`. Операция равна `version` или `doctor`. Для отказа, который нельзя отнести к известной команде, используется `cli`. Машинный режим действует и для ошибочного вызова, если `--json` распознан в области глобальных параметров. Справка всегда выводится текстом.

| Поле | Содержание |
| --- | --- |
| `status` | `ok` либо `error`. |
| `result` | Присутствует при `ok`. Для `version` содержит `version`. Для `doctor` добавляются `os`, `arch`, `go_version`, `config_file`, `data_dir`, `cache_dir` и `state_dir`. |
| `error` | Присутствует при `error`. Содержит стабильный `code`, русскоязычное `message` и, если применимо, `source`. |

В отчёте о пути присутствуют `path`, `source` и `status`. Источники — `default`, `file`, `environment`, `cli`. Статус `present` означает ожидаемый тип объекта. `missing` означает отсутствие. `wrong_type` означает, что вместо ожидаемого каталога или файла обнаружен другой объект. `unavailable` означает, что проверка метаданных завершилась ошибкой. Статус пути описывает наблюдение диагностики. Если выбранную конфигурацию нельзя прочитать или принять, операция завершается отказом.

| Код процесса | Смысл |
| --- | --- |
| `0` | Успех, включая справку. |
| `2` | `invalid_arguments` или `invalid_configuration`. |
| `1` | `configuration_io` или ошибка записи в выходной поток. Если поток недоступен, полный документ может отсутствовать. |
| `130` | `canceled`, операция отменена. |

В текстовом режиме ошибка идёт в stderr. Расширенная диагностика идёт туда же в обоих режимах. Она содержит имя операции, исход и безопасные идентификаторы отказа. Причина ошибки остаётся доступной вызывающему коду в цепочке Go-ошибок.

## Версия продукта

Единственный источник — `version.Current` в [`internal/version/version.go`](../internal/version/version.go). Версии Go, JSON-конфигурации и машинного ответа независимы от версии продукта. Несовместимое изменение машинной схемы требует отдельного решения.

- PATCH для исправления продуктового дефекта.
- MINOR для новой совместимой возможности или несовместимого изменения в `0.x` с описанием несовместимости.
- MAJOR для несовместимого изменения после `1.0`.
- Изменения документации, тестов, инфраструктуры или зависимостей без изменения поведения сохраняют версию.

Для смешанной задачи выбирается самое существенное фактическое изменение поведения. Решение о `1.0.0` принимает пользователь.
