# Anki Toolkit

Anki Toolkit предоставляет CLI для проверки собственной сборки, конфигурации и пользовательских каталогов. Поддерживаются Linux и Windows x86-64. В WSL2 запускайте Linux-бинарник. Для сборки и запуска достаточно Go из [`go.mod`](go.mod) и стандартной библиотеки. Anki, Docker и сетевые сервисы не требуются.

## Сборка и запуск

Linux и WSL2:

```sh
go build ./cmd/anki-toolkit
./anki-toolkit --help
./anki-toolkit version
./anki-toolkit doctor
./anki-toolkit --json --verbose doctor
```

Windows PowerShell:

```powershell
go build ./cmd/anki-toolkit
.\anki-toolkit.exe --help
.\anki-toolkit.exe version
.\anki-toolkit.exe doctor
.\anki-toolkit.exe --json --verbose doctor
```

Команды `help` и `version` работают без конфигурации. Без аргументов показывается справка. Глобальные флаги идут перед командой. После `version` и `doctor` допустим только `--help`. Кавычки сохраняют пробелы в путях. Для имени, начинающегося с `--`, используется форма `--config=ПУТЬ`.

`doctor` показывает версию приложения, ОС, архитектуру, версию инструментария Go, использованного при сборке, эффективные пути и их источники. Проверка метаданных сообщает о наличии объекта и его типе. Команда завершает диагностику и для ещё не созданных каталогов. Текущий CLI читает конфигурацию и метаданные путей. Операции с колодами, Anki Desktop и MCP относятся к будущим этапам.

## Конфигурация и каталоги

| Назначение | Linux и WSL2 | Windows |
| --- | --- | --- |
| Конфигурация | `$XDG_CONFIG_HOME/anki-toolkit` или `$HOME/.config/anki-toolkit` | `%APPDATA%\anki-toolkit` |
| Данные | `$XDG_DATA_HOME/anki-toolkit` или `$HOME/.local/share/anki-toolkit` | `%LOCALAPPDATA%\anki-toolkit\data` |
| Кеш | `$XDG_CACHE_HOME/anki-toolkit` или `$HOME/.cache/anki-toolkit` | `%LOCALAPPDATA%\anki-toolkit\cache` |
| Состояние | `$XDG_STATE_HOME/anki-toolkit` или `$HOME/.local/state/anki-toolkit` | `%LOCALAPPDATA%\anki-toolkit\state` |

Пустые и относительные XDG-значения приводят к указанным путям под `HOME`. Если для требуемого значения по умолчанию отсутствует допустимая абсолютная база, `doctor` возвращает ошибку.

Приоритет выбора файла по убыванию — `--config`, `ANKI_TOOLKIT_CONFIG`, `config.json` в стандартном каталоге конфигурации. Относительный путь из флага или переменной отсчитывается от рабочего каталога. Отсутствующий стандартный файл допустим, а явно выбранный файл должен быть доступен для чтения.

Приоритет каталога данных по убыванию — `--data-dir`, `ANKI_TOOLKIT_DATA_DIR`, поле `data_dir` файла и платформенное значение. Для каталога данных требуется абсолютный путь. Пустое или пробельное значение выбранного переопределения считается ошибкой. Выбранный файл проверяется целиком, даже когда его `data_dir` перекрыт более приоритетным значением. На Windows поддерживаются абсолютные пути с диском и обычные пути UNC. Пути относительно текущего диска, имена устройств и их пространства имён отклоняются.

Минимальный файл настроек:

```json
{"schema_version": 1}
```

При необходимости добавьте `"data_dir": "/srv/anki-toolkit"` на Linux или `"data_dir": "D:\\Anki Toolkit"` на Windows. Используйте один JSON-объект в UTF-8 размером до 64 КиБ. `schema_version` обязателен и равен целому числу `1`. `data_dir` можно опустить. Неизвестные и повторные ключи, `null` и несколько JSON-документов отклоняются.

`--json` выдаёт один машинный ответ в stdout, включая ошибки. Справка остаётся текстовой. `--verbose` пишет структурированную диагностику в stderr. Формат, статусы и коды завершения описаны в [архитектуре](docs/architecture.md). Лицензия продукта — [AGPL-3.0-only](LICENSE).
